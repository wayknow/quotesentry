# QuoteSentry 演示 Runbook

> 目标：用 3 分钟以内证明 QuoteSentry 不是一个“会聊天的报价器”，而是一条能审单、能阻断、能审批、能追溯的报价流程。
>
> 主线固定使用 `seed-08`；只有评委追问毛利风控时，再加演 `seed-06`。

**已录制版本**：[demo/QuoteSentry-demo-zh.mp4](../demo/QuoteSentry-demo-zh.mp4)（2 分 43 秒，中文旁白，含三轮对话）｜字幕：[demo/QuoteSentry-demo-zh.srt](../demo/QuoteSentry-demo-zh.srt)

## 1. 固定预期结果

当前仿真目录和 `seed-08` 应得到：

| 行 | 内容 | 预期状态 | 结果 |
|---|---|---|---|
| ROW 01 | `200 pcs M12x75 DIN 933 8.8 ZN` | `PRICED` | 硬匹配 `HB-M12X75-88-ZN`，客户金额 USD 465.00 |
| ROW 02 | 缺少表面处理 | `NEEDS_CLARIFICATION` | 不生成正式价格，可复制英文澄清草稿 |
| ROW 03 | `M14x60` 目录外 | `NO_MATCH` | 不使用相似 SKU 替代 |

内部参考：首轮整单报价毛利率约 21.09%，ROW 01 行毛利率约 24.67%；26 条字段证据全部回指成功。首轮客户文件只能出现 1 条可报价行。

第二轮补充第二行表面处理后，系统重新审单：ROW 01 / ROW 02 变为可报价，ROW 03 仍为目录外；客户报价为 2 行、USD 1,592.78，整单毛利率约 22.0%。

> 现场口径：`21.1%` 是整单毛利，`24.7%` 是 ROW 01 的行毛利。不要把后者说成整单毛利。

彩排实测：DeepSeek 分析约 1.3–2.0 秒，审批与导出均在 0.1 秒内；连续 3 次均为 `PRICED / NEEDS_CLARIFICATION / NO_MATCH`，客户金额稳定为 USD 465.00。

> 这些数字依赖当前仿真目录、客户折扣、汇率和规则版本。若数据变更，先更新本节再录屏。

## 4. 现场主线脚本（约 3 分钟）

### 0:00–0:20 开场

> “外贸报价员每天要把邮件和 Excel 里的询价变成可审批报价。真正难的不是写一段报价，而是判断这行能不能报、价格有没有算错、异常有没有被漏掉。QuoteSentry 做的是这段审单流程。”

指出右上角的模型选择器 `DeepSeek Flash`（可切 `DeepSeek V4 Pro`）和 `客户外发：已禁用`。

### 0:20–1:15 三轮对话审单 `seed-08`

1. 左侧选择 `演示主场景 · 三行询价`，进入“对话审单”。
2. 发送“审单，并告诉我哪些行不能报价”，指出 `PRICED / NEEDS_CLARIFICATION / NO_MATCH`。
3. 发送“第二行表面处理是镀锌”，指出人工补充证据、重新门禁、匹配和计价，整单变为 USD 1,592.78。
4. 发送“为什么第三行不能报价”，指出目录外硬失败条件与拒绝相似 SKU 替代。
5. 发送“审批并导出 CSV”，指出对话只返回审批入口，不自动执行承诺动作。

这一段的中心话术：

> “模型负责读，规则负责判断和算钱。模型返回的 SKU 和价格不会直接进入报价。”

### 1:15–2:20 审批与客户文件

1. 切到“报价审批”。
2. 指出第三行目录外被排除，客户报价包含 2 条可报价行。
3. 左侧客户视图：合计 USD 1,592.78，不含成本与毛利。
4. 右侧内部视图：成本、费用、毛利率约 22.0%、规则版本。
5. 点“审批这份报价”，审批人可改成现场评委姓名。
6. 审批完成后点 `CSV` 导出。
7. 打开 CSV，指出里面没有成本、毛利、折扣和内部异常。

> 注意：导出后整单状态仍会显示“部分待处理”，因为 ROW 02 / ROW 03 的异常尚未关闭；这不等于报价未审批。以“报价审批”页的“已导出”和 quote 状态为准。讲解时可以直接说：“这封询价仍有两条异常待跟进，但客户报价 v1 只针对可报价行，已经审批并导出。”

这一段的中心话术：

> “客户看到结果，主管看到成本，审批人对例外负责。三者不是同一张页面。”

### 2:20–2:50 审计时间线

1. 切到“审计时间线”。
2. 指出 `ANALYZED`、`APPROVED`、`EXPORTED` 三类事件。
3. 指出模型名、规则版本、输入/输出哈希、审批人和时间。

这一段的中心话术：

> “报价不是一段无法追溯的模型输出，而是一条可以复核的责任链。”

### 2:50–3:00 收尾

> “大模型会越来越强，通用抽取会越来越便宜。我们不跟模型比智商，我们守的是每家客户的目录、报价口径、异常处置和审批责任。模型可以换，这些业务资产换不掉。”

最后指出“发送已禁用”：比赛版只导出客户文件，不假装已经接入真实邮箱。

## 5. 加映：毛利越界 `seed-06`

仅在评委追问“毛利低于底线怎么办”时演示：

1. 重置演示数据或直接选择 `毛利越界 · CUST-003`。
2. 开始分析，进入“报价审批”。
3. 指出审批按钮被锁，必须由主管处理。
4. 点 `Override ROW ...`，填写主管和原因，例如：

   > 年度框架客户补件，本轮接受低于毛利底线，已获业务负责人确认。

5. 记录 override，再审批。
6. 回到审计时间线，指出 override 原因被永久记录。

必须说明：缺参和目录外不能 override，只有毛利底线可以走主管例外。

## 6. 故障兜底

| 现象 | 处理 |
|---|---|
| 左下角变成“规则模式” | 明确说明“当前是规则兜底，不是 AI 运行”，然后切录像或重新检查 Key |
| DeepSeek 超时/限流 | 不要反复点击；说明已有自动降级和录制兜底，切录像 |
| 报价已审批导致无法重新分析 | 点“重置演示数据”，重新走主线 |
| 页面数据异常 | `curl -X POST http://127.0.0.1:3001/api/reset-demo`，刷新页面 |
| 网络完全不可用 | 直接播录屏，不解释模型供应商细节 |

## 7. 演示禁止事项

- 不声称已有真实客户、真实 ROI、真实成交率。
- 不把仿真数据说成客户案例。
- 不声称模型会自动学习报价规则。
- 不现场接入真实邮箱、ERP 或客户数据。
- 不在主线中途解释过多技术栈；先让评委看到“能报的报准、不能报的停下”。
- 不临时加功能、改数据或现场调试代码。

## 8. 录屏交付标准

- 时长 1–3 分钟；当前成片 2 分 43 秒，1600 × 1000，30 fps。
- 开头 20 秒内说清客户、问题和不做什么。
- 完整包含：首轮审单 → 补参重算 → 异常解释 → 按钮审批 → 导出 → 审计。
- 结尾明确“仿真数据、模型只做抽取、客户外发禁用”。
- 视频文件与 `seed-08` 的预期结果一起归档。
