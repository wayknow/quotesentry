## 定位

**QuoteSentry（报价哨兵）是面向中国高混紧固件外贸商的询价审单 Agent。**

一句话：

> 把邮件和 Excel 询价变成可审批、可追责的报价；能报的报准，不能报的明确停下。

## 1. 问题

目标客户每天处理多规格、小批量、非标准写法的紧固件询价。报价员需要：

- 从邮件/Excel 中拆出每个产品行；
- 补齐标准、尺寸、材质、强度、表面处理和数量；
- 在私有目录中找到硬匹配 SKU；
- 按客户折扣、数量阶梯、汇率、费用和毛利底线计价；
- 把异常交给主管，再导出客户报价。

真正的损失不是“写报价慢”，而是缺参误报、相似 SKU 替代、价格算错和审批无痕。报错一次导致的返工、空运和客户信任损失，远高于报价本身。

## 2. 客户

第一批假设客户：有自有目录和客户价目表的高混紧固件外贸商，而不是所有标准件企业。

共同特征：

- 询价以邮件、Excel 和 PDF 附件为主；
- 产品规格多、单量小、客户写法不统一；
- 有客户专属折扣、毛利底线和人工审批；
- 没有预算或没有必要为报价单独上重型 ERP。

客户假设仍需在赛后用 10 家访谈验证，不能当成已经成立的市场结论。

## 3. 产品闭环

```text
邮件 / Excel
  → 逐行抽取规格与原文证据
  → 缺参 / 冲突 / 单位门禁
  → 私有目录硬匹配
  → 确定性计价
  → 人工审批 / 毛利 override
  → 客户 CSV / PDF
  → 审计时间线
```

核心边界：

- LLM 只做字段抽取和澄清草稿，不计算价格。
- SKU 必须回到目录重新硬匹配，模型返回的 SKU 不直接采用。
- 缺参、冲突、目录外、毛利越界必须阻断或进入人工处理。
- 客户文件不含成本、毛利、折扣和内部异常。
- `SEND_MODE=disabled` 时服务端拒绝发送。
- 所有客户、SKU、价格和询价均为仿真数据。

## 4. 现场证明

用 `seed-08` 展示三轮对话：

1. 首轮审单：完整行可报价；缺表面处理行待澄清；目录外行明确阻断。
2. 第二轮补参：回复“第二行表面处理是镀锌”，系统写入人工证据，重新门禁、匹配和计价；两行可报价，整单 USD 1,592.78。
3. 第三轮解释：说明目录外规格的硬失败条件，不用相似 SKU 替代。
4. 第四轮边界：用户说“审批并导出 CSV”，对话只返回审批入口，不自动执行承诺动作。

再展示审批、客户 CSV 与内部成本隔离、审计时间线。若时间允许，用 `seed-06` 展示毛利越界必须主管 override。

## 5. 为什么不是聊天套壳

判断标准：**把模型换掉，产品还剩什么？**

- 通用套壳换掉模型就什么都不剩。
- QuoteSentry 换掉模型会退化为规则模式；目录匹配、门禁、确定性计价、审批、审计和导出仍然存在。
- 规则模式覆盖清晰邮件和结构化表格，但对脏邮件的表达能力弱于 LLM；它是兜底，不是等价替代。

准确表述：

> 模型是采购来的能力，业务规则和客户数据才是产品。模型负责读，规则负责算，人负责担责。

## 6. 壁垒

公共紧固件知识不是壁垒，大模型可以学会。真正可积累的是：

- 每家客户的私有目录、协议价、折扣和替代边界；
- 缺参、冲突、目录外和毛利例外的处置记录；
- 审批链、规则版本、原文证据和客户文件隔离；
- 真实询价上的纠错数据和可复测评估集；
- 与邮件、Excel、ERP/CRM 的最后一公里集成。

壁垒不是静态规则本身，而是“客户专属配置 + 历史纠错 + 流程嵌入 + 责任链”的组合。当前仍处于仿真 Demo，壁垒是产品假设，需用真实客户样本验证。

## 7. 商业模式假设

不按 Token 收费，按业务结果和部署价值收费。待验证的方向：

- 目录初始化和规则配置的一次性实施费；
- 按报价员席位或询价量收取月度订阅；
- 私有化部署、审计和 ERP/CRM 连接器作为增值服务。

本阶段不宣称已经有付费客户或稳定定价。

## 8. 竞争与替代

| 替代方案 | 局限 | QuoteSentry 的切口 |
|---|---|---|
| 人工 + Excel | 慢、易漏项、审批无痕 | 保留 Excel 入口，增加逐行证据和门禁 |
| CRM/ERP 报价模块 | 依赖结构化数据和深度实施 | 站在 ERP 前面处理脏邮件和非标准附件 |
| 通用大模型/聊天机器人 | 能读能写，但不保证目录、价格和责任 | 模型只抽取，价格由规则计算，审批可追溯 |
| 传统报价 SaaS | 更偏流程记录 | 用 Agent 处理非结构化输入和异常分诊 |

不宣称技术首创；差异应落在目标工作流、阻断责任、证据链和中小企业可部署性。

## 9. 验证与下一步

比赛后第一周：

- 访谈 10 家目标企业，不先展示产品，先收集真实询价类型和错误案例；
- 争取 3 家设计伙伴，签署数据处理边界；
- 收集 50–100 份脱敏询价，建立人工原流程与 Agent 流程对照。

必须测量的指标：

- 字段抽取正确率；
- 目录匹配 Top-1 和目录外拒识率；
- 缺参阻断率、价格一致性、人工修订次数；
- 单封询价处理耗时、返工率和审批接管率；
- 目录初始化成本和报价员采用率。

继续投入的最低条件：至少 3 家企业反复表达同一痛点，至少 1 家愿意持续提供脱敏样例；在约定测试集上不得出现价格幻觉、目录外误报或未审批外发。

## 10. 30 秒版本

> 外贸报价员每天要把杂乱的邮件和 Excel 变成可审批报价，最容易出错的不是写文件，而是缺参、错配和价格越线。QuoteSentry 用模型读询价，用确定性规则匹配和计价，异常必须停下，最后由人审批并留痕。我们卖的不是更聪明的聊天框，而是能追责的报价流程。模型可以换，客户目录、报价规则和纠错数据换不掉。

## 11. 常见追问

### “模型都是大厂的，不就是套壳？”

> 模型是组件，不是产品。我们调用 DeepSeek 做抽取，但价格和 SKU 不由模型决定。把模型拿掉，目录匹配、门禁、计价、审批和审计仍然存在；只做提示词和聊天 UI 的产品拿掉模型就什么都不剩。未来有足够纠错数据或客户要求私有化时，可以微调或上本地小模型，但这不是当前的核心壁垒。

### “大厂不能吞掉吗？”

> 公共知识会被吞掉，我们不把 DIN/ISO 知识当壁垒。大厂拿不到每家客户的私有目录、协议价、例外规则和审批责任，也不愿意替每个客户做最后一公里实施。我们必须在这些数据和工作流上建立粘性，而不是停在文档助手。

### “为什么不用 ERP？”

> ERP 处理的是已经结构化的订单；我们的入口是报价之前那段最脏的邮件和附件。可以先不替换 ERP，后续再通过连接器把审批后的报价写回去。

### “有真实客户和 ROI 吗？”

> 没有，当前是仿真 Demo。比赛证明的是闭环和边界，真实 ROI 要在赛后用设计伙伴和脱敏询价测量。我们不会用虚构客户或宣传数字替代实测。
